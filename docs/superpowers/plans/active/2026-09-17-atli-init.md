# `atli init` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Interactive `atli init jira|confluence|bitbucket` wizard that collects URL + credentials, verifies them with one live call, writes a merged TOML profile (comment-preserving, chmod 600), and installs the SessionStart primer hook for the chosen harness.

**Architecture:** A new pure-decision module `init.py` (stdlib + `config`/`providers` imports only; runner imported lazily at verification) orchestrated by `run_init`; a `prime`-style fast path in `main.py` dispatches a new `build.create_init_app` before the mcp-atlassian import; `install.py`'s harness registry gains qwen/gigacode and promotes codex to supported via `.codex/hooks.json`.

**Tech Stack:** Python ≥3.11 stdlib (input/getpass, tomllib, urllib.parse), cyclopts 4.x, pytest with monkeypatch/tmp_path/capsys.

**Spec:** `docs/superpowers/specs/active/2026-09-17-atli-init-design.md`

## Global Constraints

- No new runtime dependencies; base install stays `cyclopts` only.
- `init.py` must never import anything that reaches `mcp_atlassian` at module level; the runner import happens inside `verify_profile`.
- Exit codes: 0 success (including clean decline at the confirmation prompt); 1 verification failure, abort after failed verification, Ctrl-C; 2 usage/config errors. `ConfigError` always maps to 2.
- Config writes are surgical (every byte outside the target `[profiles.<name>]` section and the `default_profile` line is preserved), atomic (sibling tmp file + `os.replace`), and followed by `chmod 0o600`.
- `install.HOOK_COMMAND` (`atli prime --hook-json`) is unchanged and remains the single installed command and idempotency key.
- Secrets are read via `getpass`-backed prompts; plain answers via `input`. All prompt I/O is injectable for tests.
- Collected credential values are latin-1 validated with `config.validate_credentials` semantics before acceptance.
- Match the codebase's docstring/comment idiom: module docstring states the "why", functions carry the contract.

  - `mask(value: str) -> str` — fixed `"****"` regardless of length (no length leak).

### Task 3: TOML surgery — merge, default_profile, atomic write, target path

**Files:**
- Modify: `src/mcp_atlassian_cli/init.py` (append functions)
- Test: `tests/test_init.py`

**Interfaces:**
- Consumes: Task 2's `toml_basic_string`.
- Produces:
  - `merge_profile_text(text: str, profile_name: str, values: Mapping[str, str]) -> str` — surgical, comment-preserving merge:
    - Locate the profile's table by a header line whose stripped form equals `[profiles.<name>]` or starts with that header followed by whitespace or `#` (trailing comment). The section body runs from the line after the header to the next line whose stripped form starts with `[` (any table header) or EOF.
    - Within the body, for each key in `values` (insertion order): the FIRST line whose stripped form starts with `KEY` followed by optional spaces and `=` is replaced wholesale by `KEY = <toml_basic_string(value)>` (an inline comment on the old line is dropped); keys with no such line append at the end of the body, one `KEY = "…"` line each.
    - No section found: append at EOF — a blank line (unless the text is empty or already ends with one), then the header line, then the key lines.
    - Every byte outside the section body is byte-identical. Result must parse with `tomllib` and yield exactly `values` under `[profiles.<name>]` merged over whatever else the file held.
  - `ensure_default_profile(text: str, profile_name: str) -> str` — if any line before the first table header matches `default_profile =` (stripped startswith), return `text` unchanged; otherwise insert `default_profile = "<profile_name>"` immediately before the first table-header line (a line whose stripped form starts with `[`), or append at EOF when the text has no table header. Other bytes preserved; result parses with `tomllib` with that top-level key set.
  - `write_config(path: Path, content: str) -> None` — `mkdir(parents=True, exist_ok=True)` on the parent; write to sibling `.<name>.tmp` (UTF-8), `os.replace` over the target (atomic — a crash can never truncate the file, the `install.py` pattern), then `path.chmod(0o600)` always (never loosened, both scopes).
  - `config_target_path(scope: str, *, environ: Mapping[str, str], home: Path, cwd: Path) -> Path` — `scope == "project"` → `cwd / ".atli.toml"`; `"global"` → when `environ["ATLI_CONFIG"]` is set and points at an existing file, that path (runtime reads it, so init writes it); when set but missing, raise `ConfigError` with a message in the style of `config.find_config_file`'s; otherwise `home / ".config" / "atli" / "config.toml"`. Any other scope value raises `ConfigError`.
  - Note for callers (documented in the docstring): in production, a set-but-missing `ATLI_CONFIG` already exits 2 in `main._run` before init runs; the error branch here is defense for direct/library use.

- Test: `tests/test_init.py`

**Interfaces:**
- Consumes: everything from Tasks 1–5, plus `install.install(name, scope, *, home, cwd) -> str` (raises `ConfigError` on unparsable settings, never writes then); `providers.detect_provider() -> str | None` and `providers.bitbucket_hint(provider) -> str | None` (metadata-only import — safe at `init.py` module level).

  - `run_init(service: str, *, prompt: Prompt, home: Path, cwd: Path, environ: MutableMapping[str, str], runner_factory: Callable[[], object] | None = None, out: Callable[[str], None] = print) -> int` — the whole wizard; returns the exit code. Behavior:

    2. **Wizard loop** (`while True`): `values = collect_profile(service, prompt, out)`; `scope = choose_scope(prompt)`; when `scope == "project"` → `out` the advice line "add `.atli.toml` to your repository's .gitignore"; `profile_name = choose_profile_name(service, prompt)`; `harness = choose_harness(prompt, home)`; `config_path = config_target_path(scope, environ=environ, home=home, cwd=cwd)` (a `ConfigError` here → `out(str(e))`, return 2); `out(render_summary(...))`; confirm `ask("Proceed?     3. **Verify**: `try verify_profile(...)`; on `ToolCallFailure`/`ToolRunnerError` → `out(str(error))`, then menu `ask` "1) Re-enter URL and credentials 2) Change URL 3) Abort" — 1 and 2 both `continue` the wizard loop (both resume at the URL prompt; they differ only in printed intent), 3 → return 1 (nothing written), invalid → re-prompt the menu.
    4. **Write phase** (verification succeeded): read `config_path` text (missing file → `""`; `OSError`/`UnicodeDecodeError` → `out(str(ConfigError(...)))`, return 2); `merge_profile_text` → `ensure_default_profile` → `write_config`; then hook — `harness is not None` → `out(install.install(harness, "user" if scope == "global" else "project", home=home, cwd=cwd))` (its `ConfigError` → `out(str(e))`, return 2 — the config stays written; the message explains the settings problem).
    5. **Final report** via `out`: the config path written, the profile's URL row (`jira: <url>` style like `atli profiles`), the hook line (or "hook: skipped"), and next steps — one example command for the service (jira `search` `--jql "assignee = currentUser()"`, confluence `search --query "deploy"`, bitbucket `list-repositories`) plus `atli prime` to preview the primer.
