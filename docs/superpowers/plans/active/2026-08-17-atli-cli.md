# atli — CLI wrapper over mcp-atlassian: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `atli`, a CLI exposing all mcp-atlassian operations as schema-generated cyclopts commands, with TOML profiles for multi-instance use.

**Architecture:** Fresh process per invocation: resolve profile → inject env → import mcp-atlassian's FastMCP app in-process → enumerate tools via fastmcp in-memory `Client` → build a cyclopts command tree from each tool's JSON Schema → dispatch. A single `ToolRunner` seam isolates the transport; `--profile` is pre-parsed from argv manually because profile env must be applied before any `mcp_atlassian` import.

**Tech Stack:** Python 3.11 (venv at `.venv/`), mcp-atlassian 0.23.x (fastmcp 3.4.x), cyclopts 4.22.x, pytest, setuptools backend, stdlib `tomllib`.

## Global Constraints

- Package: PyPI name `mcp-atlassian-cli`; import package `mcp_atlassian_cli` (src layout); console script binary `atli`.
- Dependencies (exact floors/ceilings, verbatim): `mcp-atlassian>=0.23,<0.24`, `cyclopts>=4.22,<5`. No other runtime deps. `tomllib` is stdlib (Python floor 3.11).
- Dev-only dep: `pytest` (installed into `.venv`, not a package dependency).
- Exit codes: `0` success · `1` tool/server/transport failure · `2` usage errors (bad args, unknown tool/command, unknown profile, config file errors).
- Output: tool text content verbatim on stdout; nothing appended, filtered, or truncated. All errors/diagnostics on stderr.
- **Import-order invariant:** no module in the `atli` entry path may import `mcp_atlassian` (directly or transitively) before profile env vars are applied to `os.environ`. `mcp_atlassian/__init__.py` reads env at import time. Violating this leaks credentials across profiles.
- `mcp_atlassian` import is the startup cost (~4.5 s cold). Do not add caches, daemons, or lazy-import optimizations.
- The server only lists tools for configured services (63 `jira_*` with Jira env, 35 `confluence_*` with Confluence env, 98 total with both; 0 with none). The CLI must handle 0..N specs.
- Verified API shapes to rely on (fastmcp 3.4.7): `Client(app)` context manager; `await client.list_tools()` → objects with `.name: str` (flat prefixed names like `jira_get_issue`), `.description: str | None`, `.inputSchema: dict`; `await client.call_tool(name: str, arguments: dict) -> CallToolResult` (raises on tool error by default); `CallToolResult.content` → list of typed blocks, text blocks have `.type == "text"` and `.text: str`.
- Verified cyclopts 4.22.5 mechanics to rely on: dynamic handlers via `func.__signature__ = inspect.Signature(...)` with **KEYWORD_ONLY** parameters (positional binding breaks `**kwargs` handlers); `--issue-key` binds parameter `issue_key` automatically; bare `--flag` sets a `bool` True; repeated `--flag v` appends to a list parameter; a handler that **returns non-None** gets its return value printed by cyclopts — handlers must print and return `None`; programmatic invocation `app(argv_list, exit_on_error=False, print_error=False)` raises `CycloptsError` subclasses on bad input and may raise `SystemExit(0)` when a return value was printed.
- Test invocation uses `.venv/bin/python -m pytest` and `.venv/bin/atli`.

### Task 3: `config.py` — profiles, env application, argv pre-parse

**Files:**
- Create: `src/mcp_atlassian_cli/config.py`
- Test: `tests/test_config.py`

**Interfaces:**
- Consumes: nothing outside stdlib (`tomllib`, `pathlib`, `os`).
- Produces (used by Task 6):
  - `SERVICE_ENV_PREFIXES: tuple[str, ...] = ("JIRA_", "CONFLUENCE_", "MCP_ATLASSIAN_")`
  - `class ConfigError(Exception)` — message is user-facing, always actionable (names the bad value and the remedy).
  - `@dataclass AtliConfig` with fields `path: Path | None`, `default_profile: str | None`, `profiles: dict[str, dict[str, str]]` (every value a string).
  - `find_config_file() -> Path | None` — check in order: `$ATLI_CONFIG` (if set but the file is missing → `ConfigError` naming that path), `./.atli.toml`, `~/.config/atli/config.toml`; first existing file wins; `None` if nothing found.
  - `load_config(path: Path | None) -> AtliConfig` — `None` → empty config (`path=None`, no default, no profiles). Otherwise parse TOML: optional top-level `default_profile: str`; `[profiles.<name>]` tables become `profiles[name]` with every value coerced to `str` (booleans as `"true"/"false"`, ints as decimal strings). Malformed TOML → `ConfigError` including the file path and the parser's message. Non-table `[profiles]` value → `ConfigError`.
  - `resolve_profile_name(flag: str | None, config: AtliConfig, env: Mapping[str, str]) -> str | None` — precedence: `flag` > `env.get("ATLI_PROFILE")` > `config.default_profile`; a resolved name absent from `config.profiles` → `ConfigError` listing available profile names (or stating none are configured).
  - `apply_profile(profile: Mapping[str, str], environ: MutableMapping[str, str]) -> None` — per-service replacement: for each prefix in `SERVICE_ENV_PREFIXES`, if the profile defines any key with that prefix, first delete **every** environ key with that prefix, then `environ.update(profile)`. Prefixes the profile doesn't touch keep their ambient values.
  - `extract_profile_flag(argv: list[str]) -> tuple[str | None, list[str]]` — scan from index 0 while the token starts with `"-"`: consume `--profile=X` (empty `X` → `ConfigError`) and `--profile X` (next token missing or starting with `"-"` → `ConfigError`); leave every other token untouched; stop scanning at the first token that doesn't start with `"-"` (the subcommand). Repeated `--profile` → last wins. Return the value (or `None`) and the remaining argv with consumed tokens removed.
  - `describe_profiles(config: AtliConfig, active: str | None) -> str` — one block per profile: active profile marked `*`, others two spaces; default profile suffixed `(default)`; for each of `JIRA_URL`/`CONFLUENCE_URL` present in the profile, a line `jira: <url>` / `confluence: <url>`. **Never prints any other variable** (tokens stay hidden). No profiles → single line `No profiles configured.` plus, when `config.path` is set, the path. Always ends with a newline.

### Task 5: `build.py` — schema-generated cyclopts command tree

**Files:**
- Create: `src/mcp_atlassian_cli/build.py`
- Test: `tests/test_build.py`

**Interfaces:**
- Consumes: `discovery.ToolSpec`, `discovery.ToolParam`; cyclopts 4.22.x mechanics listed in Global Constraints.
- Produces (used by Task 6):
  - `create_app(specs: Sequence[ToolSpec], dispatch: Callable[[str, dict[str, Any]], str], profiles_text: str | None = None) -> cyclopts.App`
  - Root `App(name="atli", ...)`; its help text documents: `--profile NAME` (pre-parsed global flag), `atli tools` for discovery, `atli <service> <tool> --help` for tool details.
  - Built-in `tools` command: signature `tools(service: str | None = None)` (cyclopts binds `--service`); prints one line per spec: service column (`"-"` for unprefixed), full command path (`jira get-issue`), then the first sentence of the description (up to and including the first `". "`, or the whole description; `"(no description)"` when empty); `--service jira|confluence` filters (unprefixed specs are listed only without a filter); empty result with a filter → prints `No tools for service '<service>'.`; zero specs at all → prints `No services configured — set JIRA_URL / CONFLUENCE_URL or a profile (see atli --help).`; returns `None` (exit 0 in all these cases).
  - Built-in `profiles` command: prints `profiles_text` when it is not `None`, else the line `No config file found.`; returns `None`.
  - Service grouping: sub-apps named `jira` and `confluence` created on demand for the services present in `specs`; specs with `service=None` register as root-level commands.
  - Per-spec handler: a function with `__signature__` built from `spec.params` — every parameter `KEYWORD_ONLY`, annotation `param.type`, required params have no default, optional params default to `param.default` (so cyclopts help shows schema defaults); `__doc__` = `spec.description`. Handler behavior: build `arguments = {k: v for k, v in kwargs.items() if v is not None}`, call `dispatch(spec.tool_name, arguments)`, `print(...)` the result, return `None` (never return the output — cyclopts prints non-None returns).
  - Registration: `service_app.command(handler, name=spec.command_name)` (or root app for unprefixed). Assumption (documented): no two specs share the same service + command name; if they do, the later registration wins silently.
